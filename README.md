# ZEVS PARTS — Telegram-бот для приёма заявок

Бот принимает контакт и запрос клиента (VIN + что нужно), создаёт карточку
в воронке **KeyCRM**, а также присылает клиенту кнопку-приглашение в группу
Telegram.

## 1. Установка

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Создание бота в Telegram

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot`
2. Задайте имя и username (например, `zeus_partsreg_bot`)
3. Скопируйте токен — вставьте в `.env` как `BOT_TOKEN`

## 3. Настройка KeyCRM

1. Зайдите в KeyCRM → **Настройки → API** → сгенерируйте API-ключ.
   Вставьте его в `.env` как `KEYCRM_API_TOKEN`.
2. (Рекомендуется) Создайте/выберите воронку, в которую должны падать заявки —
   *Настройки → Воронки*. Откройте её и посмотрите ID в адресной строке или
   в настройках воронки. Впишите в `.env` как `KEYCRM_PIPELINE_ID`.
   Если не указать — заявки попадут в первую воронку по умолчанию.
3. (Необязательно) Добавьте отдельный **источник** — *Настройки → Источники* —
   чтобы в KeyCRM было видно, что заявка пришла именно из Telegram-бота.
   ID источника впишите как `KEYCRM_SOURCE_ID`.
4. (Необязательно) Если хотите сразу назначать ответственного менеджера —
   впишите его ID как `KEYCRM_MANAGER_ID`.

## 4. Настройка .env

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN`, `KEYCRM_API_TOKEN`, `KEYCRM_PIPELINE_ID`. Ссылка на
группу (`GROUP_URL`) уже заполнена — менять не обязательно, если ссылка
на группу не изменится.

## 5. Запуск

```bash
python bot.py
```

## Как это работает

1. `/start` → приветствие ZEVS PARTS + сразу кнопка «Надіслати мій контакт»
   (для некоторых ссылок-групп — своё индивидуальное приветствие, см. ниже)
2. Клиент нажимает кнопку — Telegram сам отправляет его контакт (имя и телефон)
3. Бот просит коротко написать VIN-код авто и что нужно (запчастини, аксесуари,
   розхідники тощо)
4. После ответа бот создаёт карточку в воронке KeyCRM через API
   (`POST /pipelines/cards`) — с именем, телефоном, username, источником
   (какая ссылка/группа привела клиента) и текстом запроса клиента в заметках
5. Клиенту приходит подтверждение + кнопка-приглашение в группу Telegram

## Индивидуальные приветствия под ссылки

В `bot.py` есть словарь `WELCOME_MESSAGES` — код ссылки (после `?start=`) → свой
текст приветствия. Например, ссылка `t.me/zeus_partsreg_bot?start=leopard3`
покажет приветствие специально для владельцев Leopard 3. Если для кода
приветствия нет в словаре — показывается обычное приветствие ZEVS PARTS.

## Ссылки для групп (чтобы знать, откуда пришла заявка)

Бот поддерживает Telegram deep-linking через параметр `?start=`. Для каждой
группы делайте свою ссылку с уникальным коротким кодом (латиница/цифры/
подчёркивание, без пробелов):

```
https://t.me/zeus_partsreg_bot?start=leopard3
https://t.me/zeus_partsreg_bot?start=sealion05
https://t.me/zeus_partsreg_bot?start=chery_club
...
```

Когда клиент переходит по такой ссылке и жмёт «Старт», бот запоминает этот код
и передаёт его в KeyCRM (в комментарии к карточке). Если человек просто написал
боту напрямую (без ссылки) — источником будет `direct`.

## Ссылки для рекламы (Facebook/Telegram Ads) с UTM-метками

Для рекламных кампаний в KeyCRM создан отдельный источник **"TG ADS" (id 20)**.
Такие ссылки автоматически распознаются ботом (код начинается с `ads`) и
передают в KeyCRM метки `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`,
`utm_content` — они попадут прямо в соответствующие поля карточки.

Telegram не разрешает знаки `=`, `&` и пробелы в `?start=`, поэтому метки
кодируются компактно через `__` (два подчёркивания) как разделитель, и
короткий код перед дефисом обозначает, какая это метка:

| Код | UTM-поле |
|---|---|
| `cmp-` | utm_campaign |
| `src-` | utm_source |
| `med-` | utm_medium |
| `cnt-` | utm_content |
| `trm-` | utm_term |

Указывать нужно только то, что действительно требуется — остальное можно
не писать. Пример ссылки для рекламы в Facebook:

```
https://t.me/zeus_partsreg_bot?start=ads__cmp-litni_znizky__src-facebook__med-cpc
```

Это создаст заявку с источником "TG ADS" и заполнит `utm_campaign=litni_znizky`,
`utm_source=facebook`, `utm_medium=cpc`. Если просто использовать
`?start=ads` без меток — источник всё равно будет "TG ADS", просто без UTM.

## Отправка данных обратно в Facebook (Conversions API)

Чтобы Facebook "видел", что реклама привела к реальной заявке, и оптимизировал
показы по конверсиям, бот может отправлять событие **"Lead"** через
Facebook Conversions API. Это происходит автоматически для всех заявок,
пришедших по рекламным ссылкам (`?start=ads...`) — сразу после того, как
заявка попала в KeyCRM.

Так как заявка приходит через переписку в Telegram, а не с сайта, единственные
доступные данные для сопоставления с пользователем Facebook — номер телефона.
Он **хешируется (SHA-256)** перед отправкой — Facebook в принципе не принимает
персональные данные в открытом виде, только хеши. Match rate (процент
успешных сопоставлений) при этом будет ниже, чем с полноценного сайта с Pixel
и `fbclid`, но часть заявок всё равно засчитается, и это уже помогает
алгоритму учиться.

### Как настроить

1. Зайдите в Meta Events Manager → выберите свой Pixel (в 2026 году может
   называться "Dataset").
2. Скопируйте **ID пикселя** — впишите в `.env` как `FB_PIXEL_ID`.
3. Перейдите в *Settings → Conversions API → Generate Access Token* —
   скопируйте токен, впишите как `FB_ACCESS_TOKEN`.
4. (Необязательно) Для проверки, что события доходят: откройте вкладку
   *Test Events* в Events Manager, скопируйте код (`test_event_code`)
   и впишите его как `FB_TEST_EVENT_CODE` — тестовые события будут видны
   там же в реальном времени. **Перед боевым запуском обязательно очистите
   эту переменную** — иначе реальные события будут помечены как тестовые
   и не будут использоваться для оптимизации рекламы.

Если `FB_PIXEL_ID` и `FB_ACCESS_TOKEN` не заданы — эта часть просто не
срабатывает, ошибок не будет, всё остальное (KeyCRM, кнопка группы) работает
как обычно.

## Уведомления о новых карточках в воронке (в отдельный Telegram-чат)

Отдельный процесс `notify_server.py` принимает вебхук от KeyCRM при появлении
любой новой карточки в воронке (независимо от источника — бот, OLX, Prom,
вручную и т.д.) и шлёт уведомление в отдельный Telegram-чат.

### 1. Создайте нового бота для сотрудников

У [@BotFather](https://t.me/BotFather) создайте **ещё одного, отдельного**
бота (`/newbot`) — специально для внутренних уведомлений, не тот, что видят
клиенты. Например, назовите его `zevs_staff_bot`. Скопируйте выданный токен
— это `NOTIFY_BOT_TOKEN`.

### 2. Создайте новый Telegram-чат

Создайте новую группу в Telegram (обычным способом, через "Новая группа")
и добавьте в неё этого нового бота (из шага 1). Дайте боту право писать
сообщения в группе (по умолчанию у ботов в обычных группах есть право
писать, если не отключено явно в настройках группы).

### 3. Узнайте числовой ID этого чата

Самый простой способ — временно добавить в группу бота
[@RawDataBot](https://t.me/RawDataBot) (или похожего) и написать в группе
любое сообщение — бот покажет JSON, где будет поле `"chat":{"id": -100xxxxxxxxxx, ...}`.
Скопируйте это число (обычно отрицательное, начинается с `-100` для групп)
— это и есть `NOTIFY_CHAT_ID`. После этого бота @RawDataBot из группы можно удалить.

### 4. Разверните `notify_server.py` как отдельный Web-сервис в Railway

Это отдельный процесс с открытым портом (в отличие от основного бота,
который работает через polling без порта). Файлы — в том же репозитории
(`zevsreg`), просто второй сервис в Railway будет запускать другой файл:

1. В том же Railway-проекте нажмите **+ New** → **GitHub Repo** → выберите
   тот же репозиторий ещё раз (создастся второй сервис из того же кода).
2. В настройках нового сервиса (**Settings → Deploy**) укажите
   **Custom Start Command**: `python notify_server.py`
   (или, если Railway использует `Procfile` — там уже добавлена строка
   `web: python notify_server.py`, Railway должен предложить выбрать
   этот процесс автоматически при создании сервиса).
3. Во вкладке **Settings → Networking** нажмите **Generate Domain** —
   Railway выдаст публичный URL вида `https://your-service.up.railway.app`.
   Он понадобится для вебхука.
4. В **Variables** нового сервиса добавьте: `NOTIFY_BOT_TOKEN` (из шага 1),
   `KEYCRM_API_TOKEN` (тот же, что в основном боте), `NOTIFY_CHAT_ID`
   (из шага 3), `WEBHOOK_SECRET` (придумайте случайную строку, например
   `a8f3k29dj`).

### 5. Настройте автоматизацию в KeyCRM

Для **каждой воронки**, за которой хотите следить:

1. Зайдите в KeyCRM → **Настройки → Додатково → Автоматизація** →
   **Додати тригер**.
2. **Назва**: например, "Уведомление о новой заявке".
3. **Подія**: "Зміна статусу воронки".
4. **Значення**: выберите **первый (начальный) статус** этой воронки
   (в него всегда попадает только что созданная карточка — например,
   "Новий" или "Свободная заявка").
5. **Час виконання**: "Відразу".
6. **Умови виконання**: можно оставить пустыми (сработает для всех
   карточек), либо ограничить по источнику и т.д.
7. **Дія**: выберите **"Відправити Webhook"**.
   - **URL**: `https://your-service.up.railway.app/?secret=ВАШ_WEBHOOK_SECRET`
     (домен из шага 3, секрет из шага 4 предыдущего раздела)
   - **Метод**: `POST`
8. Сохраните триггер.

Повторите шаги 1–8 для каждой воронки, за которой нужно следить — каждая
получает свой отдельный триггер, но URL вебхука один и тот же.

### Как это работает дальше

Когда новая карточка попадает в первый статус воронки — KeyCRM шлёт вебхук
на наш сервер → сервер дозапрашивает у KeyCRM полные данные карточки (имя
и телефон контакта) → формирует и отправляет сообщение в Telegram-чат
из шага 1.

## Деплой на Railway

Бот работает через polling (без вебхука и домена), поэтому на Railway достаточно
просто держать процесс запущенным как **Worker**.

1. **Залейте проект в GitHub** (обычный `git init` → `git add .` → `git commit` → `git push`).
   `.env` в репозиторий не попадёт — он в `.gitignore`.

2. **Создайте проект на [railway.app](https://railway.app)**:
   *New Project → Deploy from GitHub repo* → выберите этот репозиторий.

3. **Задайте переменные окружения** — *Variables* в настройках сервиса, добавьте те же
   ключи, что и в `.env.example`:
   - `BOT_TOKEN`
   - `COMPANY_NAME`
   - `KEYCRM_API_TOKEN`, `KEYCRM_PIPELINE_ID`, `KEYCRM_SOURCE_ID` (опц.), `KEYCRM_MANAGER_ID` (опц.)
   - `GROUP_URL`
   - `FB_PIXEL_ID`, `FB_ACCESS_TOKEN` (опц. — для отправки заявок обратно в Facebook)

4. **Start command**: Railway сам подхватит `Procfile` (`worker: python bot.py`).
   Если попросит выбрать тип процесса — выбирайте **Worker**, не Web (боту не нужен
   открытый порт/HTTP).

5. Нажмите **Deploy** — в логах должно появиться, что бот запущен (без ошибок токена/API).
   Дальше бот работает 24/7, Railway сам перезапускает процесс при падении.

> Важно: если раньше запускали бота локально — остановите его там, иначе Telegram
> будет ругаться на два одновременных polling-подключения (ошибка `Conflict`).

## Деплой на обычный сервер (альтернатива Railway)

Если вместо Railway хотите свой VPS — любой дешёвый Ubuntu-сервер + `systemd` или `pm2`/`screen`.
Просто держите процесс `python bot.py` постоянно запущенным.
